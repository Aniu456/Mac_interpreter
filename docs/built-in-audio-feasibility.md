# 历史记录：内建输入与输出的发送方案核查

本页记录早期微信通话方案的调查，已不属于当前产品要求。当前项目是通过麦克风识别语音、显示原文和翻译结果的普通翻译器，使用说明见 [README](../README.md)。

2026-10-04：用户明确要求系统和微信均保持内建麦克风、内建扬声器。后续方案以此为约束，不以要求用户改回 BlackHole 作为完成条件。

## 已确认的现象

- 用户确认中文识别、英文翻译、本机试听正常。
- 微信使用 BlackHole 时，播放期间系统输入电平有信号，但朋友听不到；微信麦克风开启，麦克风模式为“标准”。
- BlackHole 输入与输出已经读回为 0 dB、未静音，仍未完成朋友收听验收。
- 用户切回内建麦克风后，朋友能听到直接说话。只读 Core Audio 查询也确认系统及微信实际输入均为 MacBook Pro 麦克风、输出均为 MacBook Pro 扬声器。

## 已授权的系统处理对照

固定英文分别经过同一个诊断进程的 VoiceProcessingIO 单声道输入，在旁路处理和启用处理两种状态下统计数值；不保存录音，不改变微信设置。

| 状态 | 输入 RMS | 输入峰值 |
| --- | --- | --- |
| 旁路通话处理 | −16.8 dBFS | −2.7 dBFS |
| 启用通话处理 | −75.9 dBFS | −37.5 dBFS |

朋友确认两遍都没听到。结果支持系统通话处理会严重衰减这一虚拟音频信号，但诊断进程不等于微信进程，不能据此宣称直接观察到了微信的处理结果或防诈骗拦截。

原计划同时测量的另一个原始输入引擎没有返回音频帧，该数据无效；上表仅采用正常回调的同一个 VoiceProcessingIO 输入，不把缺少回调解释为静音。

## 全内建方案的边界与下一步

可用现有本机试听验证的路径是：合成英文 → 内建扬声器 → 空气 → 内建麦克风 → 微信。之前在微信输入为 BlackHole 时完成的试听，不能替代这个验证。

这条路径存在两个限制：

1. 扬声器播放的声音可能被通话回声消除抑制。苹果 WWDC21 明确说明，“宽谱”模式仍包含回声消除，不能把切换宽谱作为已验证修复。
2. 微信麦克风保持开启时，用户原本说的中文也会被直接传给朋友，无法同时声称“仅发送译文”。

用户拒绝了单句内建播放检查，改为手机微信开免提、电脑在旁边翻译；该单设备测试未执行。0.3.0 已采用新方案，移除 Mac 微信和 BlackHole 依赖，详情见 README 与验收清单。本页保留为旧方案的调查记录。
