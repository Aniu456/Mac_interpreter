# 朋友之间语言翻译器

一个面向朋友交流的简单 macOS 翻译工具：通过电脑麦克风听取朋友说的话，显示识别原文和中文翻译。

核心流程是 **听取语音 → 识别文字 → 显示翻译**，适合面对面交流或听取电脑旁清晰播放的外语声音。也可以输入或说出中文，翻译后播放外语回复。

## 开始使用

1. 允许麦克风和语音识别权限，准备所需的语言资源。
2. 选择对方的语言和翻译服务。
3. 点击“听朋友”，让电脑麦克风听清对方的声音，查看原文和中文翻译。
4. 暂时不需要收听时，再点同一按钮“暂停收听”；字幕保留，点“听朋友”即可继续。回复时直接点“我来说”，收听自动暂停，译文播放后自动恢复。主界面不再单独提供“停止”按钮；临时中断录音、翻译或播报可按 Esc。

需要回复时，可点击“我来说”，说中文后点击“说完了”；也可以直接输入中文，再翻译并播放。播报期间暂停收音，播放结束后继续听译。

说话过程中可直接在“我的中文”里修改识别错的文字，录音继续；已编辑的文字会保留，后续识别接上新说的内容。点击“说完了”后仍按当前文字直接翻译并播放，Telegram 模式直接发送，无需额外确认。

听不清时，可在主界面最底部的“手动输入朋友说的话”框中输入或粘贴外语原文（最多 4000 字），点击“翻译成中文”。使用当前语言及手动输入区单独选择的翻译服务（默认 DeepSeek，可切换 Apple 离线），不改变实时收听的服务选择，无需开启麦克风；正在收听时会先暂停，结果显示在“对方说的话”区域。输入保留供修改或重试，翻译中可取消。

“对方说的话”中的每条原文也可以直接点击编辑。编辑时暂停收听，点击该条“重新翻译”后使用手动输入区选择的服务，在原位置更新中文，不新增重复字幕；修改尚未提交时不会将旧译文当成新原文的翻译显示。 该区域右上角的“清空”按钮会移除原文、译文和编辑草稿，并暂停收听；不影响底部手动输入或“我的回复”。

## Telegram 俄语通话

在“朋友的声音”中选择 **Telegram 通话**，对方语言选俄语，翻译服务选 DeepSeek（先在设置中配置密钥）。打开 Telegram 桌面客户端并接通通话，再点击“听朋友”。首次使用需要允许屏幕与系统音频录制、语音识别权限；如果系统要求重启应用，请重启后再试。俄语本机识别不可用时，可在设置中允许 Apple 在线语音识别。

此模式通过 ScreenCaptureKit 仅接收 Telegram 桌面客户端的音频，因此戴耳机也能显示俄语原文和中文字幕。Telegram 的提示音或其他播放声音也可能被采集；它不是单独的通话音轨。暂不支持网页版，不保存录音或屏幕画面。

发送前，在 Telegram 通话的音频设置中将 **麦克风设为 BlackHole 2ch**，**扬声器设为耳机或电脑扬声器**，并保持通话麦克风开启。本 App 仍用内建麦克风识别你说的中文。BlackHole 将本 App 播放的俄语交给 Telegram 的麦克风输入；无需改动系统默认音频设备。

接通后可点“检查连接”。助手检查 Telegram 实际启用的输入；未接通、输入仍是物理麦克风、设备断开，或输出列表包含 BlackHole 却没有独立耳机/扬声器时，会阻止发送并显示原因，不会退回扬声器假装发送成功。检查只能证明本机音频连接，好友是否听到仍需在实际通话中确认。 Telegram 使用 BlackHole 输入时，系统输出列表可能同时包含 BlackHole 和已选耳机；助手不会仅凭列表中出现 BlackHole 就认定扬声器选错。连接检查通过后会清除上一次错误提示。

点击“我来说”说中文，再点“说完了”，会翻译并直接向 Telegram 通话播放俄语。文字输入使用右侧的“翻译并发送”；有现成译文时，同一按钮变为“再次发送”，直接重发而不重新翻译。修改中文后，按钮恢复为“翻译并发送”。“试听”仅在本机播放，可在扬声器图标中选择耳机。开始播报前和播报过程中会复查连接，连接失效时停止并保留译文，修复后可重发。请轮流说话，好友不需要安装本 App。

不要把系统扬声器、其他应用输出或 Telegram 扬声器设为 BlackHole，否则额外声音也可能被好友听到。建议戴耳机。退出翻译助手后，如果要恢复直接用中文通话，请把 Telegram 麦克风改回物理麦克风。点击“复制译文”仍可自行粘贴文字给好友；这里的中文字幕不会自动显示在好友手机上。

说中文和播报期间暂停朋友字幕，结束后自动恢复；期间好友说的话不会补录，适合轮流说话。端到端效果须以实际 Telegram 通话验收为准。

在“我的回复”下方调整语速，当前档位会显示为“很慢”“较慢”“标准”“较快”或“很快”。试听和发送使用同一语速，自动保存；调整后在下一次试听或发送时生效，合成或播放期间不能修改。可点击“恢复标准”回到默认语速。

## 功能

- 显示外语原文和中文翻译，保留当前会话中的近期字幕。
- 支持 Apple 系统翻译，也可配置 DeepSeek 或 Grok。
- 英文可使用 Parakeet 本地识别；中文及其他语言使用 Apple 语音识别。
- 支持中文文字输入、语音回复和系统朗读音色选择。
- 识别或翻译失败时保留已有文字，方便检查与重试。

语言列表根据系统已安装的双向翻译资源生成。翻译语言包、语音识别资源和朗读声音需要分别准备；英文 Parakeet 模型在首次使用时下载。

## 翻译服务与隐私

- **Apple**：使用系统翻译语言包。默认要求本机语音识别；在设置中允许在线识别后，音频可能交由 Apple 服务处理。
- **DeepSeek**：在设置中保存 API Key，密钥存入 macOS 钥匙串。
- **Grok**：通过官方 Grok Build 组件进行浏览器授权，需要对应账户权限及完整的组件配置。

选择 DeepSeek 或 Grok 后，识别文字和有限的前文会发送给相应服务，可能产生服务用量。应用不保存录音，界面字幕保留在内存中；Grok 官方组件会在本机保存登录和会话记录。

识别和翻译效果取决于说话清晰度、环境噪声和语言资源。面对面模式通过麦克风收音，Telegram 模式采集该客户端音频；说中文或播放译文时，外语听译会暂停。

## 从源码运行

需要 macOS 15+、Swift 6.1+ / Xcode 命令行工具和 Git LFS。Swift 包依赖见 `Package.swift`，版本锁定在 `Package.resolved`。仓库内 Grok 组件为 Apple Silicon 版本。

使用 Xcode 时，打开根目录的 `FriendTranslator.xcodeproj`，等待依赖解析完成，选择 **FriendTranslator → My Mac**，点击 Run（`⌘ R`）。App target 已配置权限说明和 Grok 组件打包，采用 Apple Development 证书签名，避免 ad-hoc 签名随构建变化导致录制权限失效。本机需安装可用的开发证书。正式分发需另行配置签名与公证。不要只把源码目录作为文件夹打开。

也可使用命令行构建：

```sh
git clone git@github.com:Aniu456/Mac_interpreter.git friend_translator
cd friend_translator
git lfs pull
./scripts/build-app.sh
open dist/FriendTranslator.app
```

请通过 `.app` 启动。构建脚本生成 Apple Silicon 的 Release 优化应用包，包含应用图标与 Grok 组件，输出到 `dist/FriendTranslator.app`，并生成带版本号的 ZIP。默认使用 Apple Development 证书签名，未公证。可通过 `INTERPRETER_SIGN_IDENTITY` 指定其他签名身份；不要在日常使用中切换为 ad-hoc 签名，否则重建后可能需要重新授权。内部工程与模块名称为 `FriendTranslator`，应用 ID 为 `dev.benny.FriendTranslator`，项目目录为 `friend_translator`。

旧版升级后会保留语音识别偏好与音色选择，并兼容迁移本机 DeepSeek 密钥和 Grok 登录目录。新登录数据位于 `~/Library/Application Support/FriendTranslator/Grok`。应用 ID 改变后，macOS 可能重新请求麦克风、语音识别或钥匙串访问权限。

## 验证

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/module-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/module-cache" \
swift test --disable-sandbox --cache-path .build/cache --scratch-path .build/fix-verification
```

自动测试用于检查数据处理和状态切换；实际收音、识别准确度和翻译效果需要在使用中验证。参见[验收记录](docs/acceptance.md)。文档中的早期微信通话与音频路由调查仅为历史记录。

先用 `⌘Q` 完全退出翻译器，再打开当前构建版本。此前的 ad-hoc 构建在更新后可能无法沿用旧授权；如仍失败，在系统设置 → 隐私与安全性 → 屏幕与系统音频录制中移除旧条目，再添加当前使用的 `.app` 并授权，随后重新启动。Xcode Debug 包和 `dist` 下的 Release 包应统一使用同一个开发签名身份，切换签名后首次仍可能需要重新授权。
